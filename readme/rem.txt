## 14. Styling: card and image hover effects (style.css)

**Goal:** the whole card grows slightly on hover, but the picture zooms only when the pointer is over the picture itself, not when it is over the rest of the card.

**How it works**
- Card: `.card` has `transition: transform 0.3s ease, box-shadow 0.3s ease`. `.card:hover` applies `transform: scale(1.04)` and a larger shadow. The transition sits on the normal state, so the card also animates back.
- Image: each card image sits in a wrapper `<div class="img-zoom">`. The wrapper has `overflow: hidden` and works as a frame that clips the zoomed image. The image has `transition: transform 0.4s ease`. The rule `.img-zoom:hover img { transform: scale(1.06) }` makes the zoom depend on hovering the frame, not on hovering the card.
- Rounded corners: the frame inherits the top corner radius of the card so the zoomed image does not show square corners.
- Accessibility: `@media (prefers-reduced-motion: reduce)` switches the transitions off for users who prefer less motion.

**Lessons / problems solved**
- `overflow: hidden` on the image itself does nothing; the clipping must be on a parent element.
- The hover must target the wrapper (`.img-zoom:hover img`), not the card (`.card:hover .card-img-top`), to get the "image only" behaviour.
- A global `img { height: 160px; object-fit: cover }` rule affected every image on the site (logo, slideshow); it was replaced by a rule scoped to `.card-img-top`.
- Duplicate rules and an unused `overflow` rule were removed during cleanup.

## 15. Contact messages pagination and responsive admin pages

### Pagination on admin_contactfeed.php
- 10 messages per page. `$page` is read from `?page=` (at least 1), `$offset = ($page - 1) * $per_page`.
- Two queries: `SELECT COUNT(*) FROM contact_us` for the total, and a prepared `SELECT ... ORDER BY contact_us_id DESC LIMIT ? OFFSET ?` (bound as two integers) for one page.
- Three cases are handled: no messages ("No messages yet."), a page number past the end ("No more messages" with a link to page 1), and the normal table with "Page X of Y" and Prev / Next links.
- The separator between Prev and Next only shows when both links exist.
- The same pattern is used on admin_posts.php, where the active filters are also kept in the Prev / Next links (`page_link()` with `http_build_query`).

### Responsive layout (admin_contactfeed.php and admin_posts.php)
- Centered content blocks use `max-width`, `width: 100%` and `margin: 0 auto` instead of fixed pixel margins.
- Wide tables sit in Bootstrap's `table-responsive` wrapper, so only the table scrolls sideways on a phone and the page does not.
- The global `table { width: 400px; margin-left: 30px; ... }` rule was removed because it affected every table on the site.
- The three top links and the filter form are flex containers with `flex-wrap` and `gap`, so their items wrap on narrow screens.
- Pagination is centered with `text-align: center` instead of `margin-left: 580px`.
- Side menu: `#main` is no longer pushed on screens up to 768 px (`@media (max-width: 768px) { #main { margin-left: 0 !important; } }`), so the menu opens over the content. The `!important` is needed to win against the inline margin that `openNav()` sets. `closeNav()` always resets the margin. The menu has `height: 100%` and `overflow-y: auto`.
- Tested at 375 px, 768 px and a wide desktop width using the browser's device toolbar.

### Problems found and fixed
| Problem | Cause | Fix |
|---|---|---|
| Fatal error after copying the pagination block | The block still referred to `posts`, `$where_sql`, `$types` and `$params` | Adapted the queries and bindings to `contact_us` |
| Page count was wrong | The count query read the `posts` table (`FROM posts contact_us`) | `FROM contact_us` |
| A stray "1" between Prev and Next | `<?= $a && $b ?>` prints the boolean | `if` around a ` | ` separator |
| Layout broke when pages had no messages | An outer `div` was closed in only one of three branches | One closing tag after the whole `if` |
| Big gap on the left on phones | Inline `margin-left: 250px` from `openNav()` stayed on small screens | Media query with `!important`; `closeNav()` always resets |
| The `#main` styles were ignored | A comment was never closed and swallowed the rule | Closed the comment |
| Media query ignored | `(max-width)` had no value | `(max-width: 600px)` |

## Database backup and restore (Windows with XAMPP)

- `restore_db.bat`: double-click to replace the current database with that file (this overwrites the current data).
- Requirements: XAMPP's MySQL is running on port 3307, and XAMPP is installed in `C:\xampp`.
- The standard way to load `schema.sql` is the phpMyAdmin **Import** tab (see "Database setup").

1. Decision: accounts and roles
No visitor accounts. Only admins can log in.

2. Passwords
Stored hashed with password_hash(); checked with password_verify().
session_regenerate_id(true) after a successful login.
Demo account for testing: name RoboAIdemo; email and password to be listed in the README (use a fake demo password, not a real one).
3. Access control (the guard)
admin/auth.php: starts the session if needed, sends no-cache headers, checks $_SESSION['admin_id'], redirects to admin_login.php and exits.
require 'auth.php'; is the first PHP line of every admin page (not admin_login.php, not admin_logout.php).
admin_logout.php: empties $_SESSION, destroys the session, redirects to the login page. All Logout links point to it.
create.php now uses $_SESSION['admin_id'] as the post author instead of a fixed id.
4. Draft posts
post_details.php: the query is WHERE p.post_id = ? AND (p.status = 'published' OR ? = 1); the second value is 1 only when an admin session exists. Visitors asking for a draft get "Post not found."
Admins see the admin menu on every post page, plus a "Draft preview" notice on drafts, no comment form or list on drafts, and a no-store cache header.
load_comments.php and script.php check on the server that the post is published before returning or saving comments, so drafts cannot be read or commented on by guessing the id (checked with a console request).
5. Other protections
SQL injection: prepared statements in the admin pages, post_details.php, the comment scripts, login and register; the category search in post_categories.php builds its query with mysqli_real_escape_string and integer casts (be exact about this in the README).
Output: htmlspecialchars on printed values; comments are inserted in the page with textContent/text nodes in JavaScript.
Forms: server-side validation of length and email; contact form redirects after a successful send (no duplicate on refresh).
